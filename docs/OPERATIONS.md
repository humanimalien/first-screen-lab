# Обслуживание установки

## Потеря личной ссылки

Если браузер сохранил вход, участник открывает сайт и нажимает «Скопировать личную ссылку». При выходе на этом же компьютере браузер может предложить сохранённый профиль после выбора имени.

Если потеряны и ссылка, и данные браузера, участник обращается к владельцу установки. По одному имени доступ к прежнему профилю не выдаётся. Владелец сверяет личность обычным для группы способом и находит ID:

```sh
npx wrangler d1 execute DB --remote --command "SELECT id,name,team FROM members ORDER BY team,name;"
```

Восстановление для конкретного ID, например 17:

```sh
npm run recover -- 17 https://ВАШ-САЙТ.workers.dev --remote
```

Команда заменяет личную ссылку выбранного профиля и отзывает его прежние сессии. Работы и баллы не меняются. Передайте результат только самому участнику; после входа он копирует новую подписанную ссылку в шапке. Для локальной пробы замените `--remote` на `--local`. Не помещайте выведенную ссылку в Git, issue или общий чат.

«Начать отдельно с нового экрана» создаёт другой пустой профиль и не переносит работы. «Начать маршрут заново» внутри доступного профиля сохраняет историю и обнуляет баллы за собственную прежнюю попытку. Это разные действия.

## Резервные копии

D1 и R2 содержат разные части одной работы: SQL хранит ответы и ключи файлов, R2 — изображения. Резервирование одной базы не сохраняет эскизы.

Экспорт своей базы (папку `backups` создайте заранее):

```sh
npx wrangler d1 export DB --remote --output backups/workshop-2026-11-15.sql
```

Для изображений настройте выгрузку **своей** корзины R2 через совместимый с S3 клиент, например rclone, сохраняя ключи объектов без переименования, включая `screen/` и `tile/`. Руководство — [S3 API Cloudflare R2](https://developers.cloudflare.com/r2/api/s3/). Реквизиты доступа храните вне репозитория.

Для согласованной копии остановите записи на время выгрузки: проводите обслуживание вне занятия и временно закройте доступ к Worker средствами своего аккаунта. После выгрузки верните доступ. Проверьте восстановление в отдельной тестовой базе и отдельной корзине: импортируйте SQL командой `wrangler d1 execute DB --remote --file ...`, затем верните объекты R2 с прежними ключами. Импорт делайте в **новую пустую** базу и проверьте `wrangler.json` до выполнения команды. Обычная начальная миграция и полный SQL-экспорт не применяются поверх друг друга.

Сохраните отдельно `PERSONAL_LINK_SIGNING_KEY`. Его замена делает прежние подписанные ссылки недействительными. Вошедший участник сможет получить актуальную ссылку, участнику без сессии понадобится восстановление. Смена `TEACHER_ACCESS_KEY` не меняет существующие личные ссылки; она меняет ключ для создания преподавательских профилей.

## Обновления и новый поток

Перед обновлением сохраните D1 и R2. Затем `git pull`, `npm ci`, `npm run check`, `npm test`, `npm run db:remote`, `npm run deploy`. Смена кода не должна менять имена базы и корзины. Перевыпуск Worker не очищает их содержимое.

Начальная миграция предназначена для новой самостоятельной установки. Она не является инструкцией переноса действующей базы Sites. Для обновления наполненной самостоятельной базы добавляются новые миграции; существующие SQL-файлы не переписываются.

Для следующего потока создайте новую установку с другими именами Worker, D1 и R2 и новыми секретами. Старый поток можно сохранить как архив по прежнему адресу. Отдельная установка преподавателя не имеет связи с базами других преподавателей.

## Типичные затруднения

- **«Установка не завершена»** — в Worker отсутствует один из двух секретов. Локальный `.dev.vars` не переносится в облако автоматически.
- **Ошибка DB / таблица не найдена** — проверьте ID своей базы, имя привязки DB и `npm run db:remote`. Локальные миграции и облачные применяются отдельно.
- **Изображение не сохраняется** — проверьте привязку BUCKET, включённый R2 и формат/размер файла. Браузер и сервер принимают JPG/PNG до 5 МБ и 20 мегапикселей.
- **Вход пропадает** — используйте HTTPS для облачной версии, разрешите cookies и сохраните личную ссылку. Изменение домена требует получить ссылки с новым адресом.
- **В другой вкладке сменился профиль** — вкладки одного браузерного профиля используют общую сессию. Для одновременной проверки двух ролей используйте разные браузерные профили.
- **На Cloudflare недоступен R2** — сначала включите сервис в кабинете и проверьте условия аккаунта. GitHub Actions сам этого не делает.
