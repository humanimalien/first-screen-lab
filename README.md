# Полоса препятствий для первого экрана

Веб-практикум Олега Пащенко для последовательной проверки и доработки первого экрана лендинга. Один проект проходит 12 этапов; автор готовит испытание, одногруппники отвечают на готовые вопросы, автор сохраняет решение и объясняет его причину. Ответы подписаны, история версий и попыток остаётся доступной.

**Этот пакет создаёт отдельную установку для ваших групп.** В нём вымышленные имена, пустая база, собственные ключи и хранилище. Работы и личные ссылки участников действующего курса сюда не включены. Само приложение работает без ChatGPT и без Sites.

## Что понадобится

- GitHub — для вашего репозитория и, по желанию, запуска публикации через Actions.
- Cloudflare — для Worker, базы D1 и закрытого хранилища изображений R2. В аккаунте нужно включить эти сервисы. Доступность, условия подключения и тарифы проверьте перед установкой по [документации Cloudflare](https://developers.cloudflare.com/r2/pricing/).
- Node.js 24 или новее, npm и Git на компьютере, с которого вы устанавливаете приложение.

GitHub Pages обслуживает статические файлы. Здесь нужны серверные сессии, общая база ответов и загрузка изображений, поэтому сайт запускается на Cloudflare Workers, а исходники хранятся на GitHub. Свой домен необязателен: после публикации Worker получит адрес `https://ИМЯ.ВАШ-ПОДДОМЕН.workers.dev`.

## Быстрая проверка на своём компьютере

Распакуйте архив, откройте терминал в папке `first-screen-lab`:

```sh
npm ci
npm run check
npm test
npm run setup:local
npm run db:local
npm run dev
```

Откройте адрес, который напечатает Wrangler. Для локальной проверки облачный аккаунт не нужен: D1 и R2 эмулируются в `.wrangler/`. Для входа преподавателя возьмите `TEACHER_ACCESS_KEY` из созданного локального файла `.dev.vars`. **Этот файл не загружайте на GitHub.**

После остановки сервера данные локальной пробы сохраняются в `.wrangler/`. Команда `npm test` использует другую, временную базу в памяти и вымышленных участников, не меняя ваши данные.

Устанавливаемые версии зависимостей зафиксированы в `package-lock.json`; проверенная версия Wrangler — 4.50.0. Обновляйте её отдельно с повторной проверкой сборки и локальной базы.

## Настройте свои группы

Измените `workshop.config.json`: названия и ID групп, массив `participants` со студентами, массив `teachers` с преподавателями. ID должны быть уникальными и постоянными. Названия и имена можно писать кириллицей. Число групп произвольное, участники всех групп видят общую очередь и рейтинг.

```json
{
  "id": "student-anna",
  "name": "Анна Иванова",
  "group": "09"
}
```

Значение `group` должно совпадать с ID группы из `groups`. Преподавателя можно добавить в каждую группу отдельной записью с отдельным ID; это будут отдельные профили. Для общего преподавательского обзора достаточно одного профиля.

`title`, `brand` и `course` меняют название и шапку. `referenceUrl` ведёт к открытому учебному примеру «Полутень» на исходном сайте; это внешняя справочная ссылка, база вашей установки от неё не зависит. Можно заменить адрес своим примером или оставить пустую строку. Полный пример с ответами вымышленных участников не копируется в новую базу. Содержание заданий и вопросы находятся в `stages.js`.

Перед сохранением и публикацией:

```sh
npm run check
npm test
npm run build
```

Не меняйте ID участников, уже начавших работу, и названия групп посреди занятия: текущие профили привязаны к прежним записям. Для нового потока удобнее создать отдельную установку и новую базу. В открытом репозитории список имён тоже будет открыт; при необходимости используйте согласованные псевдонимы или закрытый репозиторий.

## Установите публичную версию

1. Создайте пустой репозиторий на GitHub. Загрузите **содержимое** папки пакета, включая `.github`, `.gitignore`, `package-lock.json` и `migrations`. Папки `node_modules`, `dist`, `.wrangler` и файл `.dev.vars` не нужны. Для полноценного GitHub Template владелец может включить в настройках репозитория «Template repository».
Если вы работаете через Git, команды для пустого репозитория будут такими (подставьте свой адрес):

```sh
git init -b main
git add .
git commit -m "Initial practicum setup"
git remote add origin https://github.com/ВАШ-АККАУНТ/ВАШ-РЕПОЗИТОРИЙ.git
git push -u origin main
```

2. Выполните `npx wrangler login` и войдите в свой Cloudflare. Во время установки используйте один и тот же аккаунт; его можно проверить командой `npx wrangler whoami`.
3. Выберите уникальные имена Worker, базы и корзины, например `screen-lab-design-2026`, `screen-lab-design-2026-db`, `screen-lab-design-2026-images`. Создайте хранилища:

```sh
npx wrangler d1 create screen-lab-design-2026-db
npx wrangler r2 bucket create screen-lab-design-2026-images
```

4. Измените `wrangler.json`: `name` — имя Worker; `database_name` — имя созданной базы; `database_id` — UUID из ответа `d1 create`; `bucket_name` — имя корзины. Значение из нулей — только локальная заглушка. Имена привязок **DB** и **BUCKET**, а также `migrations_dir`, оставьте как есть. Не включайте публичный доступ к R2: изображения отдаёт приложение с проверкой доступа.
5. Создайте два **разных** секрета. Для каждого получите случайную строку командой ниже, сохраните её в менеджере паролей и вставьте в соответствующий запрос Wrangler:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npx wrangler secret put PERSONAL_LINK_SIGNING_KEY
npx wrangler secret put TEACHER_ACCESS_KEY
```

Первый секрет подписывает личные ссылки. Второй нужен преподавателю при первом входе. Они не должны находиться в `workshop.config.json`, `wrangler.json` или GitHub. После входа преподаватель возвращается по автоматически созданной личной ссылке, как и студенты. Перезапуск установки не требует менять секреты.

6. Примените схему к своей новой базе и опубликуйте сайт:

```sh
npm run db:remote
npm run deploy
```

7. Откройте адрес из результата публикации. Выполните [контрольный проход](docs/INSTALL-CHECK.md), затем передайте студентам общую ссылку. Студенты выбирают группу и имя без пароля, после входа копируют личную ссылку в шапке. Личная ссылка даёт доступ к профилю: её сохраняют для себя и не публикуют в общем чате.

Команды и формат привязок сверены с официальной документацией: [Wrangler](https://developers.cloudflare.com/workers/wrangler/configuration/), [миграции D1](https://developers.cloudflare.com/d1/reference/migrations/), [R2 внутри Worker](https://developers.cloudflare.com/workers/tutorials/upload-assets-with-r2/).

## Публикация из GitHub Actions

Сначала выполните первоначальную установку выше. Затем в своём репозитории откройте **Settings → Secrets and variables → Actions** и добавьте:

| Secret | Что указать |
| --- | --- |
| `CLOUDFLARE_ACCOUNT_ID` | ID своего Cloudflare-аккаунта |
| `CLOUDFLARE_API_TOKEN` | Токен только для этого аккаунта с правами Workers Scripts: Edit, D1: Edit и Workers R2 Storage: Edit |

Готовый workflow использует созданные вами хранилища и не создаёт новые корзины. Секреты приложения `PERSONAL_LINK_SIGNING_KEY` и `TEACHER_ACCESS_KEY` остаются в Worker, повторно передавать их через Actions не нужно.

Вкладка **Actions → Deploy practicum → Run workflow** запускает проверки, миграции и публикацию. Публикация запускается вручную; обычный push и pull request выполняют проверки без облачных ключей. Публикуйте из проверенной ветки. Пример основан на [официальной инструкции Cloudflare для GitHub Actions](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/).

## Правила упражнения

Автор загружает исходный экран JPG/PNG до 5 МБ и 20 мегапикселей. В маршруте он сначала отвечает на подготовительные вопросы и открывает этап для групп, затем получает подписанные отклики и выбирает следующий кадр. На этапах с таймером просмотр длится пять секунд; на остальных экран можно рассматривать спокойно. Для некоторых испытаний понадобится отдельный рабочий прототип со ссылкой.

Каждый сохранённый ответ на вопрос о чужом эскизе — **1 балл**. Новая правка — **2 балла**, с обоснованием — **3 за всю правку**. Обоснованное решение оставить экран прежним — **3 балла**. Исходная загрузка и преподавательская самопроверка — **0**. Рейтинг разделяет баллы за свой экран и ответы другим.

Студент не может тестировать свой эскиз. Преподаватель может делать пробные ответы и видит все превью с возможностью открыть полный размер; пробы не дают баллов. У студентов в галерее маленькие растровые превью 96 × 60, полный файл доступен в ходе назначенного показа. Повторное знакомство с тем же проектом и превью влияют на первое впечатление — это учебное ограничение методики.

Свободная проверка предлагает первую ещё не отвеченную версию каждого автора. «Мой экран» содержит историю подготовки, чужих ответов и правок. Вариант можно убрать из галереи и восстановить; ответы сохраняются. «Начать маршрут заново» сохраняет прежнюю попытку в истории и снимает её баллы за свой экран, сохраняя отклики и баллы за помощь другим.

[Резервное копирование, восстановление доступа и обновления](docs/OPERATIONS.md). [Устройство кода и перенос на другой сервер](docs/ARCHITECTURE.md). [Контроль установки](docs/INSTALL-CHECK.md).

Существующий профиль по одному имени открыть нельзя; нужны личная ссылка или сохранённый вход. Для среды, где нужна подтверждённая личность, потребуется отдельная интеграция университетского входа.
